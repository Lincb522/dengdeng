# 架构

## 组件

```text
浏览器
  ├─ Vue 3 控制台：公开页、用户端、管理端
  └─ React 工作台：无限画布、资产、能力库、图像生成
                     │
SDK / CLI ───────────┼───────────────┐
                     ▼               │
              Go / Gin 单进程        │
  ┌──────────────────────────────────┴──────────────┐
  │ 控制台 API   公共模型 API   静态前端            │
  │ 鉴权/风控    协议适配        CSP/CORS/请求 ID    │
  │ 调度/限流    用量/计费        支付/推广/备份      │
  │ 监控/告警    后台任务         系统设置/审计       │
  └─────────────────────┬───────────────────────────┘
                        │
            SQLite 或 PostgreSQL
                        │
                        ├─ 上游模型与第三方中转
                        ├─ SMTP / OAuth / 支付平台
                        └─ 可选对象存储与出站代理
```

前端生产构建被嵌入 Go 二进制。根 SPA 使用 Vue，`/image-workbench/` 使用单独的 React 构建；未知页面路由回退到对应 `index.html`，未知 `/api/*`、`/v1/*` 和 `/v1beta/*` 路径返回 JSON `404`。

## 代码边界

| 目录 | 责任 |
| --- | --- |
| `backend/cmd/server` | 读取配置、初始化字段加密、连接数据库、启动 HTTP 服务 |
| `backend/internal/server` | 组装依赖、注册路由、中间件和后台任务 |
| `backend/internal/gateway` | 公共模型 API、协议转换、请求预检、故障转移和用量采集 |
| `backend/internal/service` | 调度、计费、设置、支付、推广、备份、告警、额度和后台任务 |
| `backend/internal/handler` | 用户端与管理端 HTTP 接口 |
| `backend/internal/model` | GORM 持久化模型和领域常量 |
| `backend/internal/payment` | 支付渠道的签名、下单、查询、回调与退款适配 |
| `frontend/src` | Vue 控制台和公共页面 |
| `frontend/workbench` | React 无限画布工作台 |

`server.NewRouter` 是运行时组合根。后台任务和服务实例在这里创建，避免 handler 自行建立第二套调度、计费或凭据解密路径。

## 配置与持久化

进程启动配置按“默认值 → YAML → 环境变量”合并，环境变量优先。它负责监听地址、数据库、JWT、字段加密、初始管理员、基础 SMTP、全局出站代理、备份目录和更新器入口。

管理员网页保存的运行设置位于数据库，负责站点内容、注册风控、用户默认额度、OAuth 登录、通知、能力库和网关策略。数据库设置不会改写 `.env` 或 YAML。完整边界见 [系统设置](SYSTEM_SETTINGS.md)。

数据库支持：

- SQLite：默认模式，启用 WAL、外键和 busy timeout；数据库文件权限收紧为 `0600`。
- PostgreSQL：使用 GORM PostgreSQL 驱动，适合把业务数据交给外部数据库维护。
- 自动迁移：启动时执行 GORM 模型迁移，并用种子逻辑增量补齐默认模型、价格和系统设置。

内置一致性备份当前只支持 SQLite。PostgreSQL 需要使用数据库平台自己的备份、时间点恢复和高可用能力。

## 鉴权

### 控制台会话

登录后签发 JWT。中间件从数据库重新读取用户状态、角色和会话版本，因此改密码、禁用用户或主动失效会话后，旧 Token 会被拒绝。

登录和注册还可以叠加：

- 邮箱验证码与密码重置；
- TOTP；
- step-up 二次验证；
- 会话绑定；
- Turnstile；
- IP、网段、邮箱域名和赠送额度防滥用；
- LinuxDO、钉钉、微信、OIDC、GitHub 和 Google OAuth。

OAuth state、PKCE verifier、nonce 和一次性交换码保存在数据库，可由不同进程接收回调；使用后删除，过期记录按流程清理。

### API 密钥

创建 `dd-` 密钥时保存：

1. SHA-256 摘要，用于每次请求鉴权；
2. 加密密文，用于所属用户跨设备查看、快速配置和工作台选择；
3. 短预览、状态和限制字段，用于列表展示与请求检查。

密钥原文不出现在用量、运行日志或管理端跨用户接口。可恢复密文的查看、补录和轮换受所属关系与可配置 step-up 验证保护。

## 公共请求生命周期

### 1. 读取与鉴权

公共网关接受 Bearer、`x-api-key` 和相应协议的兼容位置。请求体上限为 64 MiB。鉴权后得到用户、密钥、默认分组和多分组关系。

网关在访问上游前检查：

- 用户与密钥状态；
- 到期时间、允许/禁止 IP；
- 用户余额、有效期套餐、按次额度；
- 密钥总额度、日额度；
- 用户平台日/周/月额度；
- 用户与密钥 RPM、并发和等待队列；
- 可配置的请求风控规则。

### 2. 识别协议和模型

入口路径决定入站协议，模型目录和密钥分组决定目标平台。模型映射可以把对外名称转换成上游名称；分组还可以限制最大思考强度或把客户端档位映射成上游档位。

账号协议包括自适应、OpenAI Chat Completions、Responses 和 Anthropic Messages。只有适配器已经覆盖的组合才进行跨协议转换，未知组合返回明确错误。

### 3. 预授权与并发

计费服务根据请求、模型和当前规则计算有界预授权金额。事务同时检查可用余额与密钥额度并写入预占，避免并发请求重复使用同一余额。

请求随后占用用户、密钥和上游账号三个层级的并发槽。用户和密钥限制在公共鉴权之后执行；账号槽由调度器管理。等待时间和队列深度由运行策略限制，客户端取消会停止等待并释放已有资源。

### 4. 账号选择

候选账号必须：

- 属于目标分组，或通过多分组关系加入该分组；
- 平台与分组一致，复合分组除外；
- 状态为启用；
- 没有账号级冷却或目标模型级冷却；
- 没有超过并发、订阅、额度或重置窗口；
- 支持目标模型和协议。

排序考虑优先级、自定义顺序、当前并发和近期状态。已经在本次请求中失败的账号不会立即再次进入候选集。

### 5. 转发与响应预检

上游客户端按“账号代理 → 全局代理/直连”的配置发送请求。服务会规范化 Base URL，避免把客户端 `/v1` 和账号端点重复拼接。

非流式响应在发送给客户端前进行有界 JSON 预检；流式响应在首个有效输出前检查状态、错误事件、空流和异常结束。这样可以在客户端尚未收到内容时安全切换账号，而不是返回 HTTP 200 的空白或畸形响应。

### 6. 故障分类与转移

错误按影响范围处理：

| 范围 | 例子 | 行为 |
| --- | --- | --- |
| 请求级 | JSON、工具参数、内容策略或不支持参数 | 直接返回，不冷却其他账号 |
| 模型级 | 当前账号无模型、模型容量或模型权限 | 只冷却该账号的对应模型 |
| 账号级 | 凭证失效、账号余额、全局限流、网络或服务故障 | 冷却账号并切换候选 |

可重试错误先尝试同一分组的下一个账号，再尝试密钥选择的其他同平台分组。最大尝试次数和各类冷却时间来自运行策略。已经向客户端发送有效内容后不再切换账号，避免拼接两个上游响应。

### 7. 用量与结算

适配器从 JSON 或 SSE 中提取输入、输出、缓存创建、缓存读取和图像用量。计费服务使用请求当时的价格与倍率结算：

```text
基础用量价格
× 用户倍率
× 分组倍率
× 服务档位倍率
× 长上下文倍率（达到阈值时）
× 思考强度倍率
```

缓存和图像使用各自独立价格或倍率。最终事务释放预占、扣除实际费用、写入用量行，并按实际付费 Token 消费生成推广佣金。失败、取消和未计费用量按确定的结束状态释放预占。

## 模型发现与额度

### 模型发现

`GET /v1/models` 按密钥当前分组组装模型：

- API Key 账号：查询真实上游模型接口，合并可用账号的成功结果；全部失败时返回 `502`。
- OAuth、PAT 和 Agent Identity 等凭证：使用本地模型目录或专用实时模型接口。
- 本地目录：用于展示能力、上下文、最大输出、价格关联和无法实时发现模型的凭证。

### 上游额度

额度服务统一刷新账号剩余量、窗口重置时间、订阅到期和原始快照。官方账号使用平台专用查询；第三方 API Key 账号识别 DengDeng、Sub2API、New API、One API 等常见余额/用量格式。未知格式保留失败状态，不用站内余额代替上游额度。

健康探测与额度刷新是两件事：探测验证一次最小请求或认证路径，额度刷新读取预算窗口。两者都影响账号可用度，但不能单独证明后续业务请求一定成功。

## 支付与推广

支付渠道适配器只负责签名、下单、查询、回调和退款。`PaymentService` 持有订单状态、幂等结算、用户入账和记账本的唯一写入边界。回调和主动查询可以重复到达，但同一订单只能入账一次。

推广现金账本与 API 余额分开。佣金先进入待结算，再转为可提现；创建提现单后进入锁定。微信商家转账结果不确定时只用原商户单号查询，不换单重试。

## 监控与错误

请求路径同时产生：

- 用量明细：模型、端点、用户、密钥、分组、账号、Token、缓存、费用、IP、地区和耗时；
- 运行时指标：当前并发、队列、请求率、成功率、账号健康和服务器指标；
- API 错误：与上游请求和调度相关；
- 站点错误：浏览器、控制台 API 和后台操作相关；
- 审计日志：设置、敏感操作和状态变更；
- 告警事件：规则命中、静默和确认状态。

运行监控保留 API 错误视角，系统维护中的错误中心把站点错误与 API 错误分栏管理。二者使用请求 ID、用户、账号和时间关联，不保存完整密钥。

## 后台任务

服务启动时创建以下长周期任务：

- 支付订单到账核验；
- 推广提现对账；
- 上游账号探测、OAuth 刷新和额度同步；
- 运行指标采集与告警；
- 余额、订阅和账号额度邮件通知；
- 审计日志保留清理；
- SQLite 自动备份和系统自动快照清理。

运行指标采集任务把心跳写入数据库，并在运行监控中展示。支付、提现、探测和备份通过各自的持久化订单、探测或备份记录保留结果；这些任务不依赖浏览器页面保持打开。

## 部署与扩展边界

默认部署是一个 Go 进程和一个数据库。以下状态当前保存在进程内：

- 公共未登录接口的固定窗口限流；
- 用户、密钥和账号并发槽；
- 有界等待队列；
- 部分调度与实时指标缓存。

因此直接启动多个网关副本会得到分散的并发计数和队列。横向扩展前需要把这些状态迁移到共享协调层，并为后台任务增加单主或分布式租约。数据库中的 OAuth state、订单、用量、设置和审计记录本身可以跨进程共享。

前端 HTML 使用 `no-store`，带内容哈希的静态资源使用一年 immutable 缓存，避免发布后旧 HTML 引用已删除资源。生产更新器在完整构建成功后替换二进制，重启后检查 `/health`，失败则恢复旧二进制；它不是多实例蓝绿发布。
