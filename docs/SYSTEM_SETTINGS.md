# 系统设置

DengDeng AI 有两套配置边界：进程启动配置和数据库运行设置。两者不能互相替代。

## 配置所有权

| 配置 | 所有者 | 生效方式 |
| --- | --- | --- |
| 监听地址、数据库、JWT、字段加密、初始管理员 | YAML / 环境变量 | 重启进程 |
| 公开站点地址、基础 SMTP、全局出站代理、备份目录、更新器入口 | YAML / 环境变量 | 重启进程；部分值作为网页默认值 |
| 站点展示、注册、安全、用户默认值、登录协议、通知、第三方登录 | 数据库系统设置 | 保存后作用于新操作 |
| 网关重试、冷却、探测、队列、客户端门禁和思考倍率 | 数据库运行策略 | 保存后作用于新请求 |
| 分组、账号、模型、价格、支付、图像存储、告警 | 各自业务表 | 对新请求或新订单生效 |

管理端不读取或修改 `JWT_SECRET`、`ENCRYPTION_KEY`、数据库密码、备份口令和 root 更新器配置。系统设置中的秘密只显示“已配置”状态，不回显原文。

## 基础站点

### 名称与注册

- 站点名称和副标题用于公开页、登录页、控制台和邮件。
- “允许注册”控制邮箱和 OAuth 首次创建账户；关闭后已有账户仍可登录。
- 后台模式同时关闭公开注册和 OAuth 首次注册，并收紧公共页面入口。
- 注册邮箱允许后缀为空时接受所有合法域名；非空时只接受指定域名及其子域名。
- 禁止后缀会在发送验证码前拒绝对应域名及子域名。

`SITE_ALLOW_REGISTER` 是没有数据库设置时的启动默认值。管理员保存系统设置后，数据库值是运行时权威来源。

### 首页、导航和表格

可配置 Logo、联系方式、文档地址、首页 Markdown、自定义菜单、自定义 API 端点、默认分页大小和可选分页大小。

- Logo 与文档地址只接受 HTTP、HTTPS 或站内根路径。
- 首页内容按 Markdown 展示，不执行任意脚本。
- 自定义菜单必须包含稳定 ID、名称和 URL；可见范围为用户、管理员或全部。
- 自定义菜单与端点各最多 24 项。
- 分页选项范围为 5–500，默认值会自动加入选项列表。

## 用户初始额度

新账户读取“用户默认值”，不是从当前管理员手工修改过的任一用户余额复制。

通用默认值包括：

- 初始余额，单位为 micro-USD，`1 USD = 1,000,000`；
- 用户并发和 RPM，`0` 表示该层不限制；
- 默认分组订阅及有效天数；
- 按平台设置的日、周、月费用额度。

邮箱、LinuxDO、钉钉、微信、OIDC、GitHub 和 Google 还可以设置独立来源策略：

- 是否允许该来源参与默认发放；
- 是否要求可用邮箱；
- 首次注册是否按来源值替代通用默认值；
- 已有用户第一次绑定该来源时是否追加发放；
- 来源专属余额、并发、RPM、分组订阅和平台额度。

来源策略只有在 `GrantOnSignup` 或 `GrantOnFirstBind` 对应开关开启时才发放。首次绑定有唯一记录保护，不会因重复 OAuth 回调多次发放。

兼容字段“注册初始余额”和 `user_defaults.balance_micro` 会在保存时同步；实际注册路径读取 `user_defaults`。修改设置只影响之后创建或首次绑定的账户，不追溯修改已有用户。

## 功能开关

| 开关 | 影响 |
| --- | --- |
| 渠道监控 | 控制账号周期探测与用户渠道状态；间隔范围 15 秒至 24 小时 |
| 模型广场 | 关闭后普通用户不能读取公开模型广场，管理员仍可管理模型 |
| 推广 | 关闭推广中心和绑定入口，不删除历史关系与佣金账本 |
| 用户错误明细 | 决定普通用户是否能查看自己的失败请求详情 |
| 密钥多分组 | 决定普通用户是否能给一把密钥选择多个分组 |
| CCS 导入按钮 | 只控制控制台入口，不删除密钥或已有配置 |

## 注册与账户安全

### 邮件、TOTP 和 step-up

- 邮箱验证开启后，SMTP 已配置时注册必须提交有效验证码。
- 密码重置可以独立关闭。
- TOTP 总开关决定用户是否能绑定和使用验证器。
- 会话绑定会让设备或会话上下文参与登录有效性检查。
- step-up 用于密钥原文、轮换、敏感设置、备份、支付和分账等操作；关闭后只保留登录鉴权。
- 审计日志保留范围为 0–3650 天，`0` 表示不由保留任务自动清理。

关闭 TOTP 总开关不会自动删除用户已经保存的 TOTP 秘密。需要彻底解除某个账户的验证器时，应从账户安全或管理员流程执行禁用，而不是直接改数据库。

### Turnstile

启用 Turnstile 时必须同时填写 Site Key 和加密保存的 Secret。浏览器只收到 Site Key；Secret 只在后端验证请求时解密。

### 注册防滥用

持久化风控按以下维度计数，服务重启不会重置：

- 单 IP 每小时验证码次数；
- 单 IP 每日注册数；
- IPv4 `/24` 或 IPv6 `/64` 网段每日注册数；
- 邮箱域名每小时注册数；
- 同 IP 获得注册赠送的冷却天数；
- 手工禁止的 IP 或 CIDR。

达到阈值时可以自动写入临时封禁。重复触发会延长时长，但不超过配置的最大值。封禁原因、次数和到期时间写入审计记录。

真实 IP 依赖可信代理配置。只有来自可信代理的转发头才能作为注册和 API 的来源地址；错误地信任任意公网会让限流和 IP 规则失效。

## 登录协议与法律文档

登录协议包含修订号、是否强制同意、默认文档和多份法律文档。内置文档包括用户协议、隐私政策、可接受使用政策、服务特定条款、免责声明和开源说明。

- 强制同意时，登录和注册必须回传当前修订号。
- 修改需要重新确认的条款时应同步更新修订号。
- 文档是站点模板，不构成针对具体运营主体、地区或业务的法律意见；上线前应由运营方审核并补齐主体、联系方式、退款和数据保留规则。
- 删除或停用文档前先确认登录页默认文档仍然存在。

## 用户 OAuth 登录

支持 LinuxDO、钉钉、微信、通用 OIDC、GitHub 和 Google。每个提供商可设置：

- Client ID 与加密 Client Secret；
- Issuer、Discovery、Authorize、Token、UserInfo 和 JWKS 地址；
- Scope、回调地址和前端返回路径；
- Token 认证方式与 PKCE；
- ID Token 验签、邮箱验证要求、允许算法和时钟偏差；
- email、用户 ID 和显示名的 JSON 字段路径。

启用提供商前必须有 Client ID、Secret 和可解析的授权端点。未单独填写回调地址时，服务根据 `SITE_PUBLIC_URL` 生成 `/api/auth/oauth/:provider/callback`。

OIDC 严格验证会检查签名、Issuer、Audience、过期时间和 Nonce。Discovery 与 JWKS 必须来自运营方信任的身份提供商；不要为了让错误配置“能登录”而关闭所有验证。

上游账号 OAuth 与用户登录 OAuth 是两套配置：OpenAI、Anthropic、Gemini、Grok 上游登录使用启动配置中的 `OAUTH_*`/`XAI_OAUTH_*`，不会读取这里的用户 OAuth 提供商。

## SMTP 与通知

运行时 SMTP 可以覆盖启动配置中的主机、端口、发送者和 TLS 选择；密码加密保存。保存后先使用“发送测试邮件”验证认证、From 地址和 HTML 模板。

通知包括：

- 余额低于阈值及充值地址；
- 分组订阅即将到期；
- 上游账号额度窗口或余额告警，发送到指定邮箱。

通知失败不会回滚已经完成的模型请求或账务事务，也不会写入当日已发送标记；调度器会在下一轮再次尝试。排障时先使用测试邮件核对 SMTP 认证、TLS 和 From 地址。

## 提示词、规则和 Skill

能力库条目类型：`prompt`、`rule`、`skill`；作用域：`all`、`chat`、`image`、`video`、`audio`。

- 管理员负责条目内容、来源、版本、许可证、启用状态和能力开关。
- 用户选择保存在服务端，同一账户可跨设备同步。
- 公共 `/v1/creation-library` 只返回当前密钥所属用户可用的条目。
- 网关按请求作用域注入已选择规则和技能；图像工作台读取同一套选择。
- 远程提示词源失败时保留失败状态并允许重试，不能把失败缓存成“0 条”。

当前目录上限为 256 项。升级会按目录版本增量补齐内置条目，不覆盖管理员已编辑的同 ID 内容。

## 网关运行策略

运行策略与普通系统设置分开保存。

### 重试与冷却默认值

| 项目 | 默认值 |
| --- | ---: |
| 最大账号尝试 | 3 |
| 401/402/403 账号冷却 | 600 秒 |
| 429 冷却 | 60 秒 |
| 529 过载冷却 | 300 秒 |
| 其他 5xx 冷却 | 30 秒 |
| 网络失败冷却 | 15 秒 |

请求参数和模型能力错误按请求级或模型级处理，不应一律冷却整个账号。运行策略修改的是分类后的时长，不改变错误所属范围。

### 探测与队列默认值

| 项目 | 默认值 |
| --- | ---: |
| 探测间隔 | 300 秒 |
| 探测超时 | 12 秒 |
| 探测记录保留 | 30 天 |
| 探测并发 | 4 |
| 并发等待 | 5000 毫秒 |
| 全局等待队列深度 | 256 |

三个并发层级覆盖完整响应生命周期。`0` 只在用户、密钥或账号自身限制中表示不限；运行策略的等待时间和队列深度不能为 `0`。

### 思考强度默认倍率

| 档位 | 倍率 |
| --- | ---: |
| `none` | 0.8 |
| `low` | 0.9 |
| `medium` | 1.0 |
| `high` | 1.25 |
| `xhigh` | 1.5 |
| `max` | 2.0 |

`auto` 是控制台的“不注入档位”选项，不是计费倍率键。倍率会叠加在实际 Token 成本上；更高思考强度通常也会产生更多 Token，两者需要分别核对。

### 协议与客户端控制

运行策略还可以控制：

- 统一客户端指纹；
- Responses metadata 透传；
- Claude OAuth System 身份块；
- Anthropic 1 小时缓存 TTL 和消息缓存断点重写；
- Codex User-Agent；
- Claude Code 与 Codex CLI 最低/最高版本；
- Codex 客户端黑名单、白名单和 app-server 允许状态。

客户端门禁默认关闭。启用前先从实际请求确认版本信号、User-Agent、Originator 和 Stainless 头，否则可能拒绝所有客户端。缓存重写会改变命中率和费用，应先在测试分组对照用量明细。

## 代理、图像存储、支付与备份

这些设置有独立管理页面：

- 代理：HTTP、HTTPS 或 SOCKS5，支持测试和账号级绑定；全局 `PROXY_URL` 只作为没有账号代理时的出站配置。
- 图像存储：本地或 S3 兼容对象存储，异步图像任务依赖可用存储。
- 支付：EasyPay、支付宝、微信支付、Stripe、Airwallex；渠道秘密加密保存。
- 备份：SQLite 自动策略、手动快照、下载和删除。
- 更新：只展示并触发运维安装好的固定更新器，仓库地址由 root 配置决定。

支付金额单位、渠道字段、订单状态与对账步骤见 [支付与记账](PAYMENTS.md)。

## 保存与验证

普通字段和秘密在同一事务内保存。秘密留空表示保留当前值，明确清除才会删除。任何校验或密文写入失败都会取消整个设置更新。

保存后至少验证：

1. `/api/settings` 的公开字段符合预期且没有秘密；
2. 新注册测试账户得到正确来源策略和初始额度；
3. 登录、找回密码、OAuth 回调和协议修订正常；
4. 一次模型请求使用新的重试、缓存或思考规则；
5. 用量明细保存了实际倍率和端点；
6. 390px 移动端、桌面端和深色模式下设置表单可操作且无横向溢出。
