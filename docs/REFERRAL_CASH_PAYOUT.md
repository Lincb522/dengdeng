# 推广佣金与现金提现

推广佣金按被推广用户的实际付费 Token 消费计提，比例由推广码设置，允许 5%–10%。佣金现金账户与用户 API 余额分开：现金佣金不能直接抵扣模型调用，充值余额也不能申请推广提现。

## 绑定与计提

- 每个被推广用户只能绑定一个推广关系。
- 推广码必须启用且属于有效用户。
- 已经开始使用付费服务的账户不能通过换码改变既有归属。
- 每条用量记录最多生成一条佣金记录，`usage_log_id` 唯一约束保证计费重试不会重复计提。
- 佣金基数是实际付费 Token 消费，不是充值金额、赠送余额、退款金额或请求标价。

比例使用基点保存：`500` 表示 5%，`1000` 表示 10%。修改推广码比例只影响修改后的新用量，不重算历史佣金。

## 佣金状态

| 状态 | 含义 |
| --- | --- |
| `pending` | 已计提，等待结算期结束 |
| `available` | 已到可提现时间 |
| `reversed` | 对应消费被冲正，不再可提现 |
| `legacy_balance` | 旧版本已发到 API 余额的历史记录，不再现金打款 |

现金账户汇总四个金额：

- `pending_micro`：待结算；
- `available_micro`：可提现；
- `locked_micro`：已经进入提现单；
- `paid_micro`：已经成功支付。

佣金记录和现金账户变动在同一数据库事务中完成。达到 `available_at` 后，服务在读取或申请提现时把成熟佣金从待结算转入可提现。

## 提现账户

当前现金渠道是微信商家转账。用户提交 OpenID 后，账户状态为：

| 状态 | 行为 |
| --- | --- |
| `pending` | 等待管理员核验，不能提现 |
| `verified` | 可以创建提现单 |
| `disabled` | 已停用，不能创建新提现 |

OpenID 使用服务端字段加密保存，列表只返回掩码；SHA-256 摘要用于重复绑定检查。OpenID 必须属于选定微信支付渠道的 AppID。

## 管理端配置

在“推广分成”配置：

1. 启用现金提现；
2. 货币为 CNY；
3. 结算等待期，范围 0–90 天；
4. 最低、单笔最高和全站每日最高提现额；
5. 是否需要管理员审核；
6. 已启用且支持商家转账的微信支付渠道；
7. 商户平台审批通过的转账场景 ID；
8. 场景报备类型、真实内容和 1–32 字的转账备注。

启用前还必须满足：

- `SITE_PUBLIC_URL` 是公网可达的 HTTPS 地址；
- 微信支付 API v3 的 AppID、商户号、序列号、商户私钥、API v3 Key 和平台证书正确；
- 商户已经开通商家转账，接口安全 IP 和回调地址符合平台要求；
- 场景报备字段与商户平台审批结果完全一致，不能自行猜测。

默认配置为 7 天结算期、1 元最低提现、2000 元单笔上限、5000 元全站日上限并需要人工审核。它们是代码默认值，不代表适合任何实际运营主体。

## 提现状态机

```text
available
    │ 创建提现单，转入 locked
    ▼
REVIEW_PENDING ──批准──► QUEUED
    │ 拒绝                  │
    ▼                       ▼
CANCELLED             SUBMITTING
                            │
                 ┌──────────┼───────────┐
                 ▼          ▼           ▼
       AWAITING_CONFIRMATION PROCESSING STATUS_UNCERTAIN
                 └──────────┴───────────┘
                            │ 查询或回调
                  ┌─────────┼─────────┐
                  ▼         ▼         ▼
                SUCCESS   FAILED   CANCELLED
```

状态说明：

| 状态 | 处理 |
| --- | --- |
| `REVIEW_PENDING` | 管理员审核；拒绝后锁定金额退回可提现 |
| `QUEUED` | 等待提交给微信 |
| `SUBMITTING` | 已开始外部提交，结果尚未持久化 |
| `AWAITING_CONFIRMATION` | 微信要求用户确认收款 |
| `PROCESSING` | 微信处理中 |
| `STATUS_UNCERTAIN` | 提交或响应结果不确定，必须查询原单 |
| `SUCCESS` | 锁定金额转入累计已支付，并写现金支出账本 |
| `FAILED` / `CANCELLED` | 锁定金额退回可提现 |

同一用户同一时间只能有一个未终结提现单。创建时按当日已经申请且未失败/取消的金额检查全站日限额。

## 幂等与不确定结果

每个提现单在创建时生成唯一 `out_bill_no`，后续不会改变。外部提交发生超时、网络中断或返回无法确认的结果时，状态进入 `STATUS_UNCERTAIN`：

- 只能用原 `out_bill_no` 主动查询；
- 不能生成新单号再次转账；
- 回调和主动查询都进入同一个事务状态机；
- 已经终结的提现重复回调不会再次移动资金；
- 金额、收款人或单号与本地记录不一致时拒绝结算。

自动对账任务会处理已提交的非终结状态。人工“查询”也是查询原单，不是重新提交。

## 账本与对账

微信提现成功后，支付中心记账本写入：

```text
kind = expense
category = referral_payout
payment_method = referral_payout
```

事件键使用提现 ID，重复结算不会生成第二条支出。日常对账至少核对：

1. 本地提现单号、微信转账单号和状态；
2. 本地金额、微信金额、AppID、商户号与 OpenID；
3. `locked_micro` 是否在成功后转入 `paid_micro`，失败后退回 `available_micro`；
4. 成功单是否有且只有一条 `referral_payout` 支出；
5. `STATUS_UNCERTAIN` 是否已经主动查询，而不是长期搁置或换单重试。

推广分账涉及真实资金、税务、反洗钱、身份核验和平台资质。代码提供账务与转账流程，不替代运营主体应履行的合规义务。
