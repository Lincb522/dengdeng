# 产品规划

## 工作流

1. 从用户原话、使用数据、支持记录和当前产品确认真实问题，不先跳到功能方案。
2. 写出目标用户、触发场景、当前替代方式、期望结果和成功指标。
3. 明确范围内、范围外、依赖、约束和不会改变的既有行为。
4. 按主路径、状态、权限、数据和失败恢复定义产品行为。
5. 把规则转成可观察验收标准，覆盖正常、边界、异常和移动端或多角色差异。
6. 按用户影响、证据、成本、风险和依赖排序；未决问题明确负责人或所需证据。

编写产品契约时读取 [产品契约](references/product-contract.md)。

## 交付

- 问题和目标；
- 用户与场景；
- 范围及非目标；
- 流程、状态、权限和业务规则；
- 数据与指标；
- 失败、恢复和边界；
- 可测试验收标准；
- 依赖、风险和未决问题。

不要用“简单、智能、体验更好”等形容词代替具体行为。
