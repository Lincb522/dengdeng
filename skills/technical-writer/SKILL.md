# 技术写作

文档描述当前接受的系统，不记录被放弃的方案和常规开发过程。

## 工作流

1. 明确读者、任务、发布载体、必须回答的问题和可接受篇幅。
2. 从源码、配置、接口、命令、测试和运行结果提取事实；保留准确名称与版本。
3. 按读者执行顺序组织内容，先给结果或动作，再放背景和细节。
4. 写清前置条件、输入、输出、副作用、限制、失败恢复和可运行示例。
5. 逐项验证命令、链接、路径、字段和版本。无法验证的内容标记为未验证。
6. 删除重复标题、套话、宣传、显而易见的旁白和无行动价值的说明。

不同文档类型的必要内容见 [文档类型](references/document-types.md)。

## 完成标准

- 读者能按文档完成目标并判断成功；
- 示例不包含真实凭证或个人数据；
- 术语、大小写、单位和动作名称一致；
- 破坏性操作说明影响、备份和恢复；
- 文档没有超出当前实现的承诺。
