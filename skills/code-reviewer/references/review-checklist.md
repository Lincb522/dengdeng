# 审查检查表

## 严重程度

- **P0**：可导致大范围数据破坏、凭证泄露、远程执行或服务完全不可用，且存在现实可达路径。
- **P1**：主要功能错误、权限绕过、不可恢复的数据不一致或高概率生产故障。
- **P2**：特定条件下的错误结果、兼容性回归、资源泄漏或明显的恢复缺口。
- **P3**：影响有限但行为与明确契约不符；只有具备具体影响时才报告。

严重程度由影响和可达性共同决定，不由代码外观决定。

## 行为分区

### 输入与契约

- 空值、边界值、重复值、超长值和非法枚举是否有明确结果；
- JSON、时间、金额、编码、分页和排序是否保持既有语义；
- 新字段是否影响旧客户端、数据库旧记录或缓存内容；
- 错误码、状态码和重试语义是否一致。

### 身份与数据

- 身份验证后是否仍检查资源所有权和角色；
- 列表、导出、日志和错误是否泄露其他用户数据；
- 关键状态是否由一个所有者在原子边界内更新；
- 失败重试是否会重复扣费、创建订单或发送外部动作。

### 并发与生命周期

- 共享状态是否存在竞态、锁顺序或重复 writer；
- context、task、timer、连接、文件和订阅是否在所有路径释放；
- 取消、超时、部分失败和进程重启是否有定义；
- 缓存失效是否与数据提交顺序一致。

### 前端与客户端

- 加载、空态、错误、禁用和成功状态是否都可到达；
- 键盘、触控和窄屏是否保留关键操作；
- 异步返回顺序是否可能覆盖较新的状态；
- 用户输入、路由参数和服务端错误是否安全显示。

### 测试

- 测试是否经过真实拥有逻辑，而不是只验证 mock 或静态定义；
- 失败测试是否能在修复前稳定复现；
- 是否覆盖权限、边界、重试和升级数据；
- 并发测试是否依赖 sleep 或偶然时序。

## 不应报告

- 没有行为影响的格式或命名偏好；
- 已被当前代码明确处理的理论风险；
- 与变更无关的历史问题，除非变更使其成为新的可达路径；
- 只凭注释、函数名或扫描器标签推断的漏洞。
