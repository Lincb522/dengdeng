# 诊断手册

## 先采集什么

| 故障 | 优先证据 |
| --- | --- |
| 构建 | 完整命令、工具链版本、首个编译错误、生成步骤 |
| HTTP/API | 入站路径、状态码、请求 ID、服务端首个错误、上游响应 |
| 数据 | 事务边界、写入顺序、约束、受影响记录数、提交结果 |
| 并发 | goroutine/task 生命周期、锁、队列、取消、竞态报告 |
| 性能 | 可感知指标、基线、分段耗时、CPU/内存/I/O 剖析 |
| 浏览器 | 控制台、网络、路由、DOM 状态、实际计算样式 |
| 移动端 | OS/设备、生命周期、权限、网络、崩溃栈和布局环境 |

日志只保留与状态转换和失败相关的字段，不输出凭证、Cookie 或无关个人数据。

## 假设实验

一个有效实验应当：

1. 只改变一个可解释变量；
2. 有明确的支持结果和反驳结果；
3. 使用与故障相同的代码路径；
4. 能重复运行；
5. 不依赖破坏生产数据的操作。

如果多个尝试没有产生新证据，停止叠加修复，改为在最接近分歧处增加观测。

## 常见错误定位

- **401/403**：区分缺少身份、身份无效、权限不足和资源所有权失败。
- **402**：检查业务余额、订阅、预授权和计费单位，不与上游配额混为一谈。
- **429**：区分本地限流、上游窗口、并发槽和账户冷却；核对重试时间。
- **502**：保存上游状态、Content-Type、响应前缀和解析错误，确认是否由网关转换引入。
- **503**：检查候选账号筛选、健康冷却、额度、并发和分组绑定，确认是否确实没有可用候选。
- **空 200**：检查流式终止、内容字段映射、代理缓冲和客户端解析契约。

## 修复验证

- 原输入由失败变成功；
- 原错误路径仍返回正确、可操作的错误；
- 重试不会产生重复副作用；
- 日志能区分本地、网络和上游责任；
- 相关测试在隔离运行和完整套件中都稳定。
