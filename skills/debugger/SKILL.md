# 故障诊断

目标是找到首次发生错误的拥有边界，而不是用更多兜底掩盖症状。

## 工作流

1. 固定环境、版本、前置状态、最短操作、预期结果和实际结果。保留时间、请求 ID、状态码及相关日志位置。
2. 建立从入口到故障点的时间线，把已验证事实、竞争假设和未知信息分开。
3. 沿输入、转换、持久化、外部调用和输出逐层检查，寻找首次与预期契约偏离的位置。
4. 为最可能的假设设计单变量验证。优先增加边界日志或最小测试，不同时修改多个条件。
5. 根因成立后，修复拥有该行为的源头及直接依赖；删除仅为中间尝试增加的兜底和诊断噪声。
6. 重跑原复现路径、相邻边界和失败恢复。记录修复前后的可比较证据。

需要按故障类型选择证据和实验时，读取 [诊断手册](references/diagnostic-playbook.md)。

## 输出

- 现象与稳定复现；
- 根因及首次错误位置；
- 排除的主要假设与证据；
- 修复边界；
- 回归验证和仍未覆盖的环境。
