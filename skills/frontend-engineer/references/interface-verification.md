# 界面验证清单

## 信息与布局

- 标题、字段、状态和主要操作是否按任务顺序出现；
- 表格在窄屏是否重排为卡片或保留明确的横向浏览，而不是挤压到不可读；
- 弹窗是否受视口限制，主要操作无需先水平滚动；
- 长名称、模型、分组、地址和数字是否有可查看完整值的方式；
- 空白是否来自层级设计，而不是用无关副标题填充。

## 状态

| 状态 | 必须回答 |
| --- | --- |
| 加载 | 正在等待什么，是否避免重复提交 |
| 空数据 | 实际没有什么，下一项有效操作是什么 |
| 错误 | 哪一步失败，已知原因和可执行恢复动作 |
| 禁用 | 为什么当前不能操作，何时会可用 |
| 成功 | 数据是否已持久化，界面是否同步最新状态 |

避免先乐观显示成功、后端失败后不回滚的状态漂移。

## 响应式

至少检查：

- 320–375 px 窄屏；
- 768 px 平板或分栏边界；
- 常用桌面宽度；
- 浏览器放大 200%；
- 最长本地化文本和真实长数据；
- 软键盘打开后的表单与底部操作。

检查左右边缘、固定元素、悬浮层、滚动容器和 `position: sticky`。横向滚动只用于明确的横向数据浏览，并应在内容附近可操作。

## 可访问性

- 使用 `button`、`a`、`input`、`select` 等语义元素；
- 图标按钮有可访问名称；
- 表单错误与字段关联；
- focus 可见且不被弹窗或固定栏遮挡；
- 弹窗打开时焦点进入，关闭时回到触发控件；
- 状态不只依赖颜色；
- 动画遵循 `prefers-reduced-motion`。

## 浏览器证据

记录页面 URL、视口、操作、预期与实际结果。界面成功不能只从源码推断；至少完成一次真实交互和一次窄屏检查。
