# 前端工程

先检查框架、路由、状态所有权、API 类型、设计令牌和已有组件。不要从截图猜业务数据，也不要用新的视觉体系覆盖现有产品约束。

## 工作流

1. 明确用户任务、入口、完成状态、失败恢复和必须保留的信息。
2. 从最窄支持宽度建立内容层级，再定义宽屏重排；组件受父容器约束，不以固定屏幕尺寸作为页面基础。
3. 使用语义控件和项目现有状态路径。异步请求处理加载、空数据、错误、重试、取消和过期响应。
4. 文案使用产品术语和直接动作；帮助文本只保留能防止错误的信息。
5. 检查键盘顺序、焦点、标签、对比度、减少动效、触控尺寸和长文本。
6. 在真实页面执行关键路径，查看控制台和网络，并检查桌面、窄屏、长内容和深色模式。

开始视觉与交互验收前，读取 [界面验证清单](references/interface-verification.md)。

## 完成标准

- 主要任务在支持视口中完整可达；
- 没有意外横向滚动、重叠、裁切或屏幕外操作；
- 加载、空态、错误和禁用状态表达真实条件；
- 鼠标、键盘和触控均可完成关键操作；
- 浏览器控制台无本次变更新增错误，网络请求符合接口契约。
