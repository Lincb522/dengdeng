# 后端工程

先读取入口、调用方、领域模型、迁移、配置、错误映射和测试。运行行为与已发布契约优先于注释和预期设计。

## 工作流

1. 写出本次行为契约：输入、身份、状态前提、输出、副作用、失败和重试结果。
2. 找到拥有该状态的服务或事务边界。避免在 handler、定时器和后台任务中分别实现同一规则。
3. 设计成功路径和失败路径，再修改最少的拥有代码与直接依赖。
4. 持久化必需状态后再执行可重试的非必需副作用；外部操作需要幂等键、有限超时和明确的对账方式。
5. 传播 context 和取消，关闭连接、流、文件、锁和 goroutine；不要用 sleep 代替同步。
6. 增加能覆盖当前行为分区的测试，并运行数据竞争、迁移或集成验证中与风险相关的部分。

涉及接口、事务、并发或外部系统时，读取 [服务端契约](references/service-contracts.md)。

## 完成标准

- 状态规则只有一个所有者，写入和账务边界原子；
- 重试、超时、取消和进程重启后的结果有定义；
- 错误保留原因并在 API 边界映射为稳定契约；
- 日志、指标和追踪支持定位失败但不包含敏感值；
- 测试经过真实逻辑并覆盖至少一个相关失败路径。
