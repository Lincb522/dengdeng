# 服务端契约

## 接口边界

- handler 负责协议解析、身份上下文和响应映射；
- service 负责业务不变量、状态转换和事务；
- repository/store 负责持久化语义，不决定业务权限；
- adapter 负责外部协议与内部模型转换；
- scheduler/worker 调用同一 service，不复制业务规则。

新抽象只有在隐藏真实复杂度或统一多个当前调用方时成立。不要为单次调用增加透传层。

## 数据与事务

- 用数据库约束保护唯一性、外键和不可为空的不变量；
- 余额、库存、并发槽和状态机更新使用条件写或事务锁，检查受影响行数；
- 金额和 Token 使用整数最小单位，明确舍入发生的位置；
- 迁移兼容现存数据，提供回滚或向前修复路径；
- 写入成功后再发布事件；事件失败若允许重试，需持久化待处理状态。

## 幂等与重试

| 操作 | 要求 |
| --- | --- |
| 创建订单 | 客户端或服务端幂等键，重复请求返回同一业务结果 |
| 支付回调 | 外部交易号唯一，验签和金额匹配后原子入账 |
| 用量结算 | 请求 ID 唯一，预扣与最终扣费可对账 |
| 队列任务 | 租约或状态机，重复投递不重复产生副作用 |
| 上游请求 | 仅对可安全重放的阶段重试，并限制次数与总时长 |

## 并发

- 明确共享状态的唯一 writer；
- 锁内不做网络、磁盘或未知耗时操作；
- 通道和队列有容量、等待上限和关闭所有权；
- fan-out 有并发上限，首个成功或取消时及时停止剩余任务；
- 后台 goroutine 有父 context、退出路径和测试可见状态。

## 错误与观测

错误应保留可判定类别和根因。协议边界输出稳定错误码、简短说明和恢复动作；内部日志记录请求 ID、资源 ID、阶段、耗时和上游状态。不要通过字符串匹配承担长期错误分类。
